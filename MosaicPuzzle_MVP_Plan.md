# Mosaic Puzzle — MVP План разработки (финальная версия)

Дата: 2026-06-29  
Платформа MVP: **Web**  
Базовая сетка: **6x6** (с поддержкой расширения)

## Принятые решения

1. Генерация деталей: **Backtracking** (гарантия корректного разбиения), реализовано через **Strategy + Interface**.
2. Дизайн: **Placeholder** до завершения MVP.
3. Обучение: **1 уровень** на MVP. В будущем — отдельный обучающий уровень под каждую новую механику.
4. Контент: сервис загрузки через интерфейсы, текущая реализация через **resources**, дальнейшие реализации подключаются без изменения бизнес-логики.

## Архитектурные правила (обязательные)

- SOLID / DRY / KISS.
- Один класс — одна ответственность.
- Никаких God Objects и циклических зависимостей.
- Никакого `any`.
- Никаких магических чисел.
- Все межмодульные взаимодействия — через EventBus.
- Расширяемость через интерфейсы и стратегии:
  - загрузка контента
  - генерация пазла

---

## Definition of Done для MVP

MVP считается завершенным, если:

1. Игра запускается в Web и корректно проходит 1 учебный уровень.
2. Работают drag/rotate/snap/lock.
3. Победа определяется автоматически.
4. Архитектура поддерживает замену:
   - провайдера контента,
   - алгоритма генерации.
5. Код соответствует strict TypeScript и принятым архитектурным правилам.

## Детализация реализации (дополнение из обсуждения)

### 1) Конфигурируемость 6x6 с расширением

- Базовое значение: `GRID_SIZE = 6`.
- Все системы должны принимать `gridSize` как параметр уровня (а не хардкод).
- Ограничения генератора и валидатора настраиваются через конфиг (минимум/максимум размер детали, допустимые формы, порог snap).

### 2) Strategy/Interface для загрузки контента

#### Контракты
- `IImageLoader` — загрузка изображения по id.
- `ILevelProvider` — получение данных уровня.

#### Текущая реализация MVP
- `ResourcesImageLoader` — загрузка из `resources`.
- `ResourcesLevelProvider` — данные уровня из `resources`/json.

#### После MVP (без изменения бизнес-логики)
- Добавление реализаций: `UrlImageLoader`, `ApiLevelProvider`, `RemoteBundleProvider`.

### 3) Strategy/Interface для генерации пазла

#### Контракт
- `IPuzzleGenerationStrategy` — единый интерфейс генерации фигур/разбиения.

#### Текущая реализация MVP
- `BacktrackingGenerationStrategy`:
  - гарантирует валидное покрытие сетки,
  - допускает контроль ограничений по сложности,
  - медленнее жадного подхода, но предсказуемее по качеству.

#### После MVP
- Возможность подключить `GreedyGenerationStrategy` или гибридную стратегию для ускорения генерации на больших сетках.

### 4) Обучение и прогрессия на MVP

- В MVP реализуется **один** учебный уровень.
- Параметры учебного уровня:
  - сетка 6x6,
  - упрощенный набор фигур,
  - минимальная когнитивная нагрузка.
- Пост-MVP: отдельный учебный уровень под каждую новую механику (вращение, туман, ложные детали и т.д.).

### 5) Scope MVP (Web-first)

- В MVP поддерживается только Web.
- Input ориентирован на pointer/mouse (touch также через pointer events, без платформенных расширений).
- Оптимизация и тесты — только для web runtime.

### 6) Placeholder-дизайн до пост-MVP

- UI и детали используют placeholder визуал.
- Основной фокус: корректность механик и архитектуры.
- Финальная художественная стилизация переносится на следующий этап.
